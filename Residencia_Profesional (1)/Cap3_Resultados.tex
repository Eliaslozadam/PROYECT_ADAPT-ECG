\chapter{Desarrollo y resultados}

El presente capítulo describe el proceso de desarrollo del sistema inteligente con reentrenamiento continuo para la detección adaptativa de patologías cardiovasculares, estructurado en cuatro fases secuenciales. Se detallan los materiales, herramientas y métodos empleados en cada fase, seguidos de los resultados cuantitativos obtenidos y su análisis.

\section{Materiales y métodos}

\subsection{Entorno de desarrollo}

El desarrollo del proyecto se realizó en dos entornos complementarios. El preprocesamiento de datos, el entrenamiento del modelo base y el reentrenamiento continuo se ejecutaron en Google Colaboratory con aceleración por GPU NVIDIA Tesla T4 (16 GB VRAM), accesible de forma gratuita a través de Google Drive. La evaluación comparativa formal, el análisis estadístico y la interfaz de usuario se ejecutaron localmente en un equipo con Windows 11, procesador Intel Core i7, 8 GB RAM y Python 3.12 en un entorno virtual. Las bibliotecas principales utilizadas fueron PyTorch 2.x, scikit-learn, NumPy, SciPy, Matplotlib y Streamlit. La gestión del código fuente se realizó mediante Git y GitHub.

\subsection{Conjunto de datos: MIT-BIH Arrhythmia Database}

Se utilizó la MIT-BIH Arrhythmia Database \cite{Moody2001}, disponible públicamente en PhysioNet, descargada mediante la biblioteca \texttt{wfdb} de Python. La base de datos comprende 48 registros de ECG de dos canales con una frecuencia de muestreo de 360 Hz y una duración de aproximadamente 30 minutos por registro. Las etiquetas de los latidos fueron agrupadas en cinco clases según el estándar AAMI EC57 \cite{AAMI2012}: N (normal), S (supraventricular ectópico), V (ventricular ectópico), F (fusión) y Q (no clasificable). El conjunto de datos resultante tras el preprocesamiento comprende 94,627 latidos.

\subsection{Preprocesamiento de señales ECG}

El protocolo de preprocesamiento aplicado a cada registro incluye los siguientes pasos:

\begin{enumerate}
\item \textbf{Filtrado pasa-banda}: Se aplicó un filtro Butterworth de orden 4 con frecuencias de corte de 0.5 Hz (paso alto) y 40 Hz (paso bajo), implementado con la función \texttt{sosfilt} de SciPy con filtrado bidireccional para eliminar el desfase de fase.

\item \textbf{Detección de picos R}: Se empleó el detector de máximos locales de SciPy (\texttt{find\_peaks}) con umbral adaptativo y distancia mínima de separación equivalente a 300 latidos por minuto.

\item \textbf{Segmentación de latidos}: Se extrajo una ventana de 71 muestras centrada en cada pico R detectado (35 muestras anteriores y 36 posteriores), equivalente a aproximadamente 197 ms a 360 Hz.

\item \textbf{Normalización \textit{z-score}}: Cada ventana de 71 muestras se normalizó individualmente a media cero y desviación estándar unitaria, eliminando las variaciones de amplitud entre latidos.

\item \textbf{Asignación de etiquetas}: Las etiquetas originales de cada pico R fueron mapeadas a las cinco clases AAMI EC57 mediante un diccionario de correspondencia.
\end{enumerate}

Los latidos cuya ventana de extracción excedía los límites del registro, así como aquellos con desviación estándar igual a cero (señal plana), fueron descartados. El dataset resultante fue guardado en formato NumPy (\texttt{X.npy} con dimensiones $94{,}627 \times 71$ y \texttt{y.npy} con dimensiones $94{,}627$).

\subsection{Entrenamiento base del modelo}

El modelo ECG\_CNN fue entrenado sobre el 80\% del dataset (75,702 latidos), reservando el 20\% restante (18,925 latidos) como conjunto de validación. El proceso de entrenamiento se configuró con los siguientes hiperparámetros: 30 épocas, tamaño de \textit{minibatch} de 64 latidos, optimizador Adam con tasa de aprendizaje $\alpha = 10^{-3}$ y decaimiento de peso $\lambda = 10^{-4}$, y función de pérdida NLLLoss con pesos de clase ponderados inversamente proporcionales a la frecuencia de cada clase en el conjunto de entrenamiento. El modelo entrenado fue guardado en el archivo \texttt{models/ecg\_cnn\_base.pth}.

\subsection{Módulo de reentrenamiento continuo}

El módulo de reentrenamiento continuo implementa la técnica de Replay Buffer para mitigar el \textit{Catastrophic Forgetting}. El dataset de 94,627 latidos fue dividido en 5 lotes secuenciales de aproximadamente 18,925 latidos cada uno, simulando la llegada progresiva de nuevos datos de pacientes. Esta división temporal es la metodología estándar en investigación de \textit{Continual Learning} para evaluar el rendimiento de los modelos adaptativos.

El Replay Buffer tiene una capacidad máxima de 2,000 latidos, con política de reemplazo aleatorio cuando está lleno. En cada lote de reentrenamiento se mezclan los nuevos datos con el 50\% de muestras extraídas aleatoriamente del buffer. El reentrenamiento se realiza durante 5 épocas por lote con tasa de aprendizaje reducida $\alpha = 10^{-4}$, preservando las representaciones aprendidas durante el entrenamiento base. El modelo adaptativo resultante fue guardado en \texttt{models/ADAPT-ECG-RETRAINED.pth}.

\subsection{Evaluación comparativa}

La evaluación comparativa formal se realizó sobre el conjunto de validación completo (lotes 1 a 4, 75,702 latidos), comparando el modelo estático (sin reentrenamiento) contra el modelo adaptativo (con Replay Buffer). Las métricas calculadas fueron: exactitud (\textit{Accuracy}), F1-Score macro, F1-Score ponderado, precisión y sensibilidad por clase. Adicionalmente, se aplicó la prueba estadística de McNemar para verificar la significancia estadística de las diferencias observadas.

\subsection{Fase 2: Entrenamiento base del modelo CNN}

El modelo ECG\_CNN fue entrenado durante 30 épocas en Google Colaboratory con GPU NVIDIA Tesla T4. La exactitud de validación alcanzó el \textbf{94.00\%} al finalizar el entrenamiento. La curva de aprendizaje mostró convergencia estable sin señales de sobreajuste, validando la adecuación de la arquitectura y los hiperparámetros seleccionados. El modelo base entrenado fue guardado en \texttt{models/ecg\_cnn\_base.pth} y sirvió como punto de partida para el módulo de reentrenamiento continuo.

\subsection{Análisis estadístico: Prueba de McNemar}

Para verificar si la diferencia de rendimiento entre ambos modelos es estadísticamente significativa, se aplicó la prueba de McNemar sobre las predicciones de ambos clasificadores en el conjunto de validación. Los resultados obtenidos fueron:

\begin{equation}
\chi^2_{\text{McNemar}} = 5342, \quad p \approx 0
\end{equation}

El valor de $p \approx 0$ es extremadamente inferior al nivel de significancia estándar de $\alpha = 0.05$, por lo que se rechaza la hipótesis nula de que ambos clasificadores tienen el mismo rendimiento. La diferencia en exactitud entre el modelo adaptativo (97.83\%) y el modelo estático (93.54\%) es estadísticamente significativa, confirmando que el reentrenamiento continuo con Replay Buffer produce una mejora genuina y no atribuible al azar.

\subsection{Interfaz de usuario}

Se desarrolló una interfaz de usuario con Streamlit (\texttt{src/ui/app.py}) que permite la interacción en tiempo real con el sistema. La interfaz cuenta con tres pestañas principales:

\begin{enumerate}
\item \textbf{Análisis ECG}: Permite seleccionar registros de la base de datos MIT-BIH o cargar un archivo CSV con señal ECG propia. Aplica el preprocesamiento completo, ejecuta la inferencia con el modelo adaptativo y muestra las predicciones por clase junto con las probabilidades de confianza.

\item \textbf{Reentrenamiento}: Permite iniciar sesiones interactivas de reentrenamiento incremental sobre registros seleccionados, actualizando el Replay Buffer y los pesos del modelo en tiempo real. Muestra las métricas de rendimiento antes y después de cada sesión.

\item \textbf{Historial}: Presenta la evolución temporal de la exactitud y el F1-Score a lo largo de las sesiones de reentrenamiento, almacenada persistentemente en \texttt{models/retrain\_history.json}.
\end{enumerate}

La interfaz se inicia con el comando \texttt{streamlit run src/ui/app.py} desde el directorio raíz del proyecto.
